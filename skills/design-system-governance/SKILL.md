# Design System Governance

Treat the system as a product and organisational capability. Establish surfaces, users, technologies, ownership and adoption constraints first.

Maintain traceability across foundations, semantic tokens, components, patterns and compositions. Cover states, responsive behaviour, content, localisation, data density, accessibility and recovery. Do not imply Figma/code parity unless verified.

Define contribution criteria, decision rights, review cadence, versioning and deprecation. Measure adoption, duplication avoided, accessibility defects, design-to-build time and change failure—not only library size.
