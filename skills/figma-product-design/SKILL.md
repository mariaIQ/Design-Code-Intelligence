# Figma Product Design

Use available Figma capabilities and their required prerequisite skills before reading or writing a file. Confirm the target file, page and node when ambiguity could affect existing work.

Design from user tasks, evidence and constraints. Use auto layout, variables, semantic tokens, components and variants so the design can map predictably to code. Include responsive behaviour, interaction states, content extremes, error recovery and keyboard/focus intent.

Maintain a practical Figma-to-React contract: component name, purpose, variants, properties, states, token bindings, responsive rules and accessibility notes. Do not claim code parity until both sources are inspected.

For full screens or flows, show hierarchy and navigation before decorative polish. For design-system work, distinguish foundations, components, patterns and product compositions. Use prototypes only where motion or state transition improves understanding.
